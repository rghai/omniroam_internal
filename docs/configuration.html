Founder configuration guide

What can change easily, what stays protected and what turns live ordering on.

Brand, markets and prices should be easy to edit. Credentials and write permissions must remain outside the code and under strict control.

Safety modes

Mode Payment Supplier Purpose
Demo Fake Fake UI and support testing, no money
Test payment Opn test Fake/off Realistic checkout without supplier spend
Bounded supplier test Fake/test Live, capped Explicit cheap-plan experiments only
Production Opn live Live Only after all launch gates pass

Payment writes and supplier writes have separate switches. A production deployment alone must never enable live ordering.

Founder-editable configuration

  • Selected Signal Friendly brand, visible name treatment, Omi-and-friends copy and semantic colour tokens
  • Launch market, display currencies, destination order and featured packages
  • AUD retail price, plan labels, value messages and comparison disclosures
  • Support contact, help content and escalation wording
  • Campaign copy, experiment variants and analytics destinations
  • Margin floors, provided changes require human approval and version history
Currency policy at launch

AUD is the binding customer checkout currency. Other currencies are labelled reference estimates only. Opn settlement is recorded in THB and supplier cost in USD. Do not switch a display estimate into a charge currency without a separate commercial, payment and reconciliation review.

Secret placeholders

Names belong in the guide; values do not.

Use protected Vercel environment variables for provider secrets. Public/browser keys may be exposed only where the provider explicitly intends it. Rotate development credentials before production.

  • OPN_PUBLIC_KEY : browser tokenisation, environment-specific
  • OPN_SECRET_KEY : server only
  • OPN_WEBHOOK_SECRET : server only
  • ESIMACCESS_ACCESS_CODE : server only
  • ESIMACCESS_SECRET_KEY : server only
  • DATABASE_URL : server only
  • EMAIL_PROVIDER_KEY : server only

Replaceable provider seams

The application selects adapters through configuration: fake or Opn payments; fake or eSIMAccess fulfilment. A future provider must satisfy the same internal contract. Brand and commercial configuration never imports provider-specific code.

Supplier safety controls
  • Supplier writes disabled by default
  • Explicit maximum test cost and allowed SKU list
  • Deterministic transaction identifier
  • Request rate limit and bounded retry policy
  • Emergency kill switch independent of deployment

Before production

  1. Choose the final brand direction and delete unused concepts.
  2. Approve launch market, retail prices and margin floors.
  3. Provision database, backups and reconciliation jobs.
  4. Configure separate preview and production environment values.
  5. Rotate every credential used during development.
  6. Verify webhooks, idempotency, payment ambiguity and refund workflow.
  7. Complete accessibility, mobile and coverage QA.
  8. Record founder approval before enabling supplier writes.
