Build cheaply first. Keep the growth plumbing portable.

CleverTap is deliberately not a Phase 1 dependency. Omniroam owns orders, catalogue decisions, consent, campaigns and loyalty; external tools remain replaceable adapters.

Current product state

Checkout

Opn test keys are configured in Vercel. The hosted-card failure was traced to CSP blocking the payment frame; Omise/Opn frame and connection origins are now permitted. A real browser test-mode payment is still required before declaring checkout fixed.

My eSIMs

The header now routes to the authenticated account. Customers sign in once and see all orders linked to their verified Clerk email addresses. Email + order-number recovery remains the guest fallback, not the primary experience.

Staff auth

Staff RBAC accepts any verified Clerk email that exactly matches the staff allowlist. Unauthorized screens expose sign-out/switch-account. Clerk Organizations are not required; the dashboard must use optional membership or have Organizations disabled.

Catalogue

The database catalogue is authoritative whenever it is enabled. Approved + enabled SKUs publish to the storefront; disabling removes them. Supplier-changed or withdrawn SKUs are forced back to review. The old hard-coded launch catalogue no longer reappears merely because zero DB rows are approved.

Catalogue operating rules

  • New supplier SKUs start disabled and Not reviewed.
  • Supplier changes disable an existing SKU and return it to review.
  • Supplier-withdrawn means the SKU disappeared from the latest supplier feed. The word must not be shown for a normal pricing failure.
  • Enable validation distinguishes missing price, margin/contribution failure and actual supplier withdrawal.
  • Commercial minimums remain A$3 contribution and 35% margin. Staff see the actual figures and suggested compliant minimum price.
  • Select-all selects the current filtered visible result set; expand to all matching database rows later only if needed.

Still requires browser/provider proof

  1. Clerk dashboard: disable required Organization membership, then sign out and back in as the intended staff account.
  2. Run Japan Light and Thailand Light through Opn test checkout. Verify one charge maximum, correct return/3DS behaviour and no duplicate fulfilment.
  3. Sign in through My eSIMs and verify order history without entering an order number; test email code plus enabled social providers.
  4. Approve one safe catalogue SKU, verify it appears without deployment, disable it and verify it disappears. Repeat with a new destination.
  5. Create and activate one generic website promotion and verify render. Add preview/test-send before relying on marketing email campaigns operationally.
  6. Verify loyalty after a real qualifying paid order. Do not enable monetary reward redemption yet.

Known limitations

  • Loyalty checkout-credit redemption is intentionally not implemented yet.
  • Referral points are not implemented.
  • Campaign preview/test-send, file upload, conversion dashboard and visual multi-step journey builder remain pending.
  • Some pre-purchase lifecycle presets need an identified pre-order/prospect context before they can work beyond order-linked events.
  • SMS, WhatsApp and LINE marketing remain disabled until providers are selected and tested.

How the next Work/Codex session should operate

Use GitHub, Vercel and Notion connectors for code, CI, deployments, logs and documentation. Use browser/computer control only for provider dashboards, interactive OAuth, hosted Opn payment, visual storefront proof and live signed-in account/staff flows. Do not spend browser time on work a connector can verify.

Non-negotiable rules

  • No secret, QR, activation value, customer data or private token in GitHub, Notion or public evidence.
  • No duplicate charge or duplicate supplier order for one customer action.
  • Refund execution remains human-authorised.
  • Customer order ownership is always enforced server-side.
  • Changed supplier data must not silently remain public.
  • Marketing consent must be re-checked at delivery time.
  • CleverTap stays silent unless founders explicitly enable it.
  • Customer and founder copy uses Australian English and no em dashes.
