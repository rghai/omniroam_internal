Release-blocking work

  1. Configure the production security hash secret and eSIM data-encryption key, then confirm the current migration.
  2. Verify Opn and eSIMAccess webhook authenticity, replay protection and event storage.
  3. Complete payment-to-supplier-to-email reconciliation and an operator mismatch queue.
  4. Complete 3-D Secure return handling and test an uncertain payment outcome.
  5. Implement the first fraud rules and human refund procedure.
  6. Verify the next owned email domain and monitored reply inbox.
  7. Configure separate staff authentication and access logs.
  8. Arrange an independent penetration test before material scale.

Accepted temporary limitations

  • The content security policy still permits inline styles and scripts needed by the current application. Replace these with nonces as part of production hardening.
  • Four moderate findings remain in development-only build tooling. The production dependency audit has no known findings. Do not ship development tooling into the runtime image.
  • Turnstile enforcement is off during local testing. Server verification is present but requires the production secret and host list.
  • The current work is a threat-model review, dependency audit, static control review and local regression run. It does not claim independent adversarial testing.
